HANABI — Travel Planning Platform

Designing and building an end-to-end travel planner using React, Firebase, and Google Maps APIs.

Role
Product Designer & Front-End Developer
Duration
5 weeks · Individual project
Technology
JavaScript, React, Firebase, Google Maps API, Responsive Web Design
+ add product screenshots

01

The problem

Travel planning often requires switching between multiple tools:

Search→Maps→Saved places→Articles→Notes→Itinerary

I wanted to explore whether these fragmented tasks could be combined into one experience, so I designed and developed HANABI as an end-to-end travel planning platform where users could discover locations, save places, and build itineraries without constantly switching apps.

02

From idea to working product

I owned the project end to end: defining the core travel-planning problem and scope, designing a single-page planning experience around maps and itinerary building, building the interface in JavaScript and React, integrating Google Maps for location search and visualization, using Firebase to persist user-generated travel data, and shipping a working web product from scratch within five weeks.

03

Key features

Location search

Search destinations and visualize results directly on the map.

Saved places

Save interesting destinations and retrieve them later.

Map-based discovery

Explore locations spatially instead of relying entirely on text search.

Trip builder

Create trips and organize selected locations into daily itineraries.

Travel content

Connect travel articles with saved landmarks, turning inspiration into planning.

Google authentication

Securely access personalized travel information.

04

Technical decisions

Building HANABI taught me how product decisions translate directly into engineering constraints. I worked with React for component-based UI, React Hooks for state management, Firebase/Firestore for persistent user data, the Google Maps API for search and location rendering, Google Authentication for account access, and responsive design for desktop and mobile. Instead of handing requirements to an engineer, I had to make the tradeoffs myself.

Reflection — Building it myself changed how I write requirements

HANABI changed how I work with engineers as a Product Manager. Building a product myself taught me that even a seemingly small feature can involve API limitations, state management, data structures, edge cases, and dependencies — and that experience helps me write more realistic requirements, ask better technical questions, and understand the tradeoffs behind engineering estimates.
